# 서울 생활권 체감더위 골목 단위 시간별 추정

서울시 도시데이터센서(S-DoT)의 **점 관측**을 3D 건물 음영·천공률·지형·녹지와 결합해, 서울 전역 **25m 격자(969,212칸)의 시간별 기온과 그 불확실성**을 추정한다.

기상청 5km 격자는 서울을 43칸으로 덮는다. 그 한 칸 안에서 25m 기온은 **P95−P05 2.40℃** 갈린다(2026-08-06 16시). 이 프로젝트는 그 2.40℃를 골목 단위로 풀어낸다.

---

## 방법

```
T(셀, 시각) = t_reg(시각) + Δ(셀, 시각)
               ─────────      ─────────────
               서울 광역값     동시각 편차 — 이 프로젝트가 추정하는 것
```

- **`t_reg`**: 그 시각 서울 전체를 대표하는 스칼라. 학습·평가에서는 센서 중위, 운용에서는 기상청 단기예보 중위를 쓴다
- **`Δ` 점추정 (B3)**: 같은 시각 이웃 센서의 IDW 보간값을 피처로 넣고, 정적 공간 피처와 함께 LightGBM으로 학습한다. 학습 센서의 IDW는 자기 관측을 빼고(leave-one-out) 계산한다 — 안 빼면 정답이 피처에 샌다
  - 음영: 센서·셀마다 **180방위 수평선 프로파일**을 한 번 구해 두고, 시각별 태양 위치와 대조해 `shadow_margin`(태양 고도 − 장애물 앙각)을 얻는다. 416만 행에 광선을 쏘지 않고 배열 조회 한 번으로 끝난다
  - 천공률(SVF) · 건물 밀도 · 표고·경사·지형 차폐(DEM 90m) · 녹지·포장면 비율
  - **센서와 격자가 같은 계산 코드를 쓴다** (`scripts/horizon_core.py`). 다르면 추론 때 모델이 본 적 없는 피처 분포를 받는다
- **`Δ` 분포**: 24시간 궤적의 조건부 분포 — 이분산 척도 + 시각 간 상관 + **t(ν=4) 꼬리** + **Mondrian split conformal** 보정
  - 처음에는 Flow Matching을 계획했다. 근거였던 「궤적이 다봉」을 87,444궤적으로 실측해 보니 **분산 혼합**이었고, 더 단순한 모수 분포로 바꿨다 (`core/model/traj_probe.py`)

검증은 **지점 단위 5-fold**다 — 평가 센서는 학습에서 통째로 빠진다. 모델 비교는 fold별 짝지은 차이와 `t(4)`로 한다.

## 결과

온도 수치는 별도 표기가 없으면 **MAE(℃)**다. 개선율은 `(기준 − 대상) ÷ 기준`이고 **양수면 오차가 줄었다**.

| 비교 | 값 |
|---|---|
| B0a 서울 단일 대표값 | 0.762 ± 0.028 |
| B0b 기상청 5km 해상도 | 0.662 ± 0.032 |
| B1 IDW 공간 보간 | 0.622 ± 0.031 |
| **B3 IDW + 정적 공간 피처** | **0.5582 ± 0.0256** — B1 대비 **개선 +10.2%** (`t(4)=12.74`) · B0b 대비 +15.7% · B0a 대비 +26.8% |
| 각 지점의 진짜 평균 편차를 아는 정적 지도 (오라클, in-sample) | 0.5995 — **B3가 이긴다.** 시간 정보가 정적 지도로는 닿을 수 없는 영역을 연다 |
| 오차 바닥 (105m 이내 센서 쌍으로 추정) | ≈ 0.455 — B3는 바닥의 1.23배 |

| 분포 지표 | 값 |
|---|---|
| conformal 보정 후 적중률 | 명목 50 / 80 / 90 / 95% → 실측 **50.0 / 80.0 / 90.0 / 95.0%** |
| CRPS | 점추정 0.5580 → 분포 **0.4133** (개선 +25.9%) |
| 33℃ 초과 시간 CRPS | 점추정 대입 0.608 → **0.428** (개선 +29.6%) |
| 음영·SVF 기여 | 크기 1.4%, 5 fold 전부 같은 부호 — `t(4)=4.11` **유의** |

**전향 검증** — 2026-08-28 예보로 고정해 둔 예측을 9/5에 쌓인 관측과 대조했다. 학습에 없는 날짜(56,547행 · 센서 780)에서 광역 균일 0.6083 → **0.5533℃ (개선 +9.0%)**. 시간 외삽에서도 공간 이득이 남는다.

## 실행

`uv` · **Python 3.12 고정** (`pyproject.toml`이 `>=3.12,<3.13`). 모든 명령은 **리포 루트에서** 실행한다.

```bash
uv sync                    # 기본 (torch 없음)
uv sync --extra fm         # torch 포함 — CUDA 12.1 서버용
cp .env.example .env       # 인증키 입력 — scripts/README.md 「인증키」
```

```bash
# 1. 데이터 → train.parquet · 격자 피처  (순서·입출력은 scripts/README.md)
uv run python scripts/build_train.py

# 2. 분할 → 기준선·모델 → 지표   (core/는 패키지라 -m으로 실행 · 전체 순서는 core/README.md)
uv run python -m core.eval.build_splits
uv run python -m core.baseline.b0_regional
uv run python -m core.baseline.b3_hybrid
uv run python -m core.metrics.evaluate --verify

# 3. 재현성 검증 — 플랫폼을 옮기거나 계산 코드를 고친 뒤
uv run python scripts/verify_pipeline.py            # 기준값과 전 항목 대조
uv run python scripts/verify_pipeline.py --quick    # B1·B3 생략
```

화면은 줌에 따라 바뀐다 — 멀리서는 서울 전역 2D 래스터, 가까이 가면 건물 3D와 시각별 그림자. 날짜는 폭염일 2026-08-06과 평온일 2026-07-15 두 개다.

## 표기 규칙

- **온도는 절대 기온인지 동시각 편차인지 반드시 구분한다.** 수치 대부분이 편차(같은 시각 서울 센서 중위와의 차이)다. `−1.36℃`는 영하가 아니라 **중위보다 1.36℃ 시원하다**는 뜻이다. 절대 기온은 여름 데이터라 항상 영상이다
- **퍼센트는 「개선율」 한 축이다.** `개선 +15.7%` / `악화 −17.1%`처럼 단어를 붙인다
- **모든 공간 연산은 EPSG:5186(미터)에서 한다.** 서울시 UPIS(5174, Bessel 타원체)는 `pyproj` 정식 변환을 거친다 — 그냥 대입하면 datum shift 100~200m가 조용히 섞인다
